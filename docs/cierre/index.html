Día 2 · Martes 6 de octubre

Colecciones, variables y entornos

Ámbitos: de más amplio a más concreto

Global pm.globals
Collection pm.collectionVariables
Environment pm.environment
Data pm.iterationData
Local pm.variables.set

Si dos ámbitos definen la misma variable, gana el más concreto.

Un mismo request, tres servidores: {{baseUrl}}

dev http://localhost:8080Desarrollo local
staging http://localhost:8081Otras contraseñas, tokens de 60 s
prodSolo lectura y con mucho cuidado

También: valor inicial frente a valor actual, variables dinámicas ({{$guid}}, {{$randomInt}}) y pre-request scripts.

La clave del día: ninguna URL escrita a mano. Cambiar de entorno es cambiar de servidor sin tocar la colección. Montamos dev y staging en dos puertos.

El test que aporta valor comprueba la lógica

const pizza = pm.response.json();

pm.test("price = coste × 1,20", () => {
  const esperado = Math.round(
    pizza.ingredientsCost * 1.2 * 100) / 100;
  pm.expect(pizza.price)
    .to.be.closeTo(esperado, 0.001);
});
¿Por qué closeTo y no equal? En JavaScript:
0.1 + 0.2 = 0.30000000000000004
pm.test y pm.expect con Chai. Empezamos por status, tiempo y Content-Type, y acabamos en la regla de negocio del precio.

Día 5 · Patrón destacado

Login transparente para toda la colección

// Pre-request de la COLECCIÓN
const token = pm.environment.get("token");
const exp = Number(pm.environment.get("tokenExpiresAt"));
if (!token || Date.now() > exp - 10_000) {
  pm.sendRequest({
    url: pm.variables.replaceIn("{{baseUrl}}/api/auth/login"),
    method: "POST", /* body con username y password */
  }, (err, res) => {
    const body = res.json();
    pm.environment.set("token", body.accessToken);
    pm.environment.set("tokenExpiresAt",
      Date.now() + body.expiresIn * 1000);
  });
}
1
¿Hay token vigente?
Si no caduca en los próximos 10 s, no hace nada
2
Si no, login por debajo
pm.sendRequest no aparece en la colección
3
Guarda token y caducidad
Cualquier request funciona aunque se lance suelta
Este patrón se mejora el día 6 usando el refresh token en lugar de repetir el login completo.

Para llevar al proyecto

Checklist antes de producción

  • Ninguna URL escrita a mano: todo pasa por {{baseUrl}}
  • Los flujos crean sus datos y los borran al terminar
  • Ningún secreto en valores iniciales ni ficheros versionados
  • En verde con newman run desde una máquina limpia
  • Autenticación heredada de la colección, con refresh automático
  • Integrada en el pipeline con informe JUnit
  • Tests globales de tiempo, formato y errores
  • Documentada, con ejemplos de respuesta
  • Cada request de escritura tiene al menos un caso de error
Usadla como lista de revisión antes de dar por buena cualquier colección del equipo.
